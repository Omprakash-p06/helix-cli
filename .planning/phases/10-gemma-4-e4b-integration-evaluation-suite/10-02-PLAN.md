# Plan 10-02: BackendCapabilities Runtime Probe — Function Calling & Context Window

## Objective

Populate `BackendCapabilities.function_calling` and `BackendCapabilities.context_window`
at agent startup by probing the live llama-server endpoint. Currently these fields are
defined but never populated (always default `false`/`0`). This plan adds a startup probe
that queries `/v1/models` (and optionally `/props`) to detect actual server capabilities
and sets `function_calling: true` when the backend supports tool calls, and populates
`context_window` from the `AppConfig.context_size` value (which already gets set from
the Python config).

This plan runs in Wave 1 in parallel with 10-01. It does not depend on 10-01 but both
must pass before Wave 2 plans execute.

## Requirements Coverage

- MOD-01 extended: BackendCapabilities fields are populated with real values for downstream
  consumers (context engineering layer from Phase 08, tool dispatch in main.rs)

```rust
use reqwest::Client as HttpClient;

/// Probe the llama-server backend to populate BackendCapabilities.
/// - Queries `/v1/models` to detect if server is running and get model ID
/// - Sets `function_calling: true` if the response model id contains "gemma" or "functionary"
///   OR if `/props` endpoint returns `has_jinja: true`
/// - Sets `context_window` from `app_config.context_size` (already loaded from Python config)
/// - Sets `streaming: true` always (llama-server always supports streaming)
/// - Sets `grammar_sampling: true` always (llama.cpp always supports GBNF grammar)
/// - Returns the updated `BackendCapabilities` — caller assigns to `config.backend_capabilities`
pub async fn probe_backend_capabilities(
    app_config: &AppConfig,
    client: &HttpClient,
) -> BackendCapabilities {
    let base = app_config.base_url.trim_end_matches('/');
    let models_url = format!("{}/v1/models", base);

    let mut caps = BackendCapabilities {
        function_calling: false,
        streaming: true,          // llama-server always supports streaming
        grammar_sampling: true,   // llama.cpp always supports GBNF
        context_window: app_config.context_size as u32,
        model_id: String::new(),
    };

    let body = match client.get(&models_url).timeout(std::time::Duration::from_secs(5)).send().await {
        Ok(r) => match r.text().await {
            Ok(t) => t,
            Err(_) => return caps,
        },
        Err(_) => return caps,
    };

    // Parse model_id from /v1/models response
    if let Ok(json) = serde_json::from_str::<serde_json::Value>(&body) {
        if let Some(id) = json["data"][0]["id"].as_str() {
            caps.model_id = id.to_string();
            let id_lower = id.to_lowercase();
            // Enable function_calling for models known to support tool calls natively
            if id_lower.contains("gemma") || id_lower.contains("functionary") || id_lower.contains("hermes") {
                caps.function_calling = true;
            }
        }
    }

    // Optionally check /props for has_jinja (confirms Jinja2 template is active → tool calling works)
    let props_url = format!("{}/props", base);
    if let Ok(r) = client.get(&props_url).timeout(std::time::Duration::from_secs(3)).send().await {
        if let Ok(t) = r.text().await {
            if let Ok(props) = serde_json::from_str::<serde_json::Value>(&t) {
                if props["has_jinja"].as_bool().unwrap_or(false) {
                    caps.function_calling = true;
                }
            }
        }
    }

    caps
}
```
